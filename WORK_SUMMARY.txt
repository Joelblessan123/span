          0. CURRENT PRODUCT OVERVIEW (2026) — WHAT IS LIVE NOW
================================================================================

This section is the up-to-date feature rundown. Older sections below are
historical narrative; if anything conflicts, prefer this section.

ORGANIZATION NAME: SPAN = Students for Patient Advocacy Nationwide.

DASHBOARD & PERMISSIONS
- Five permission flags on members: volunteer, applications, bills, registration,
  and blog (content / Medium workflow). Execs effectively have all five.
- Dashboard layout and section order are permission-driven (see docs/DASHBOARD_FUNCTIONS.md).

BILLS — PUBLIC SITE (BillsPage)
- Public bills list with filters, search, pagination, collaborators, LegiScan links.
- Proposal viewing: PDF and/or Google Doc–style links as configured per bill.
- Optional “hidden” approved bills: live in admin/submitter views but not on the public list.
- Bill cards can show LegiScan-derived status timeline (including House/Senate rows when data allows).

BILLS — DASHBOARD (EXEC & BILL MEMBERS)
- Bill Management (execs) and Bill Submission (members with bills permission).
- Assigned work: execs create assignments for members who have bills access; assignees
  see “Assigned to me,” update status (e.g. in progress / completed), and submit deliverables
  (Google Doc link and PDF URL as required by the workflow).
- Open pool: members can claim unassigned tasks from a shared pool where enabled.
- After exec approval, workflow supports publishing to the public bills side with prefilled
  bill fields (PDF upload still required where applicable). US state values are normalized
  for consistency.
- Research (SPAN): browse internal proposal corpus with filters (state, number, keywords,
  status), expand for detail, doc/PDF preview, collaborators.
- Research (Legislature): search LegiScan bills; detail includes metadata, sponsors, history,
  and readable bill text when available.
- Compare: side-by-side SPAN proposal + LegiScan bill in one view.
- Outreach (exec): tab for legislator/outreach tracking tied to approved bills and
  bill_outreach_targets (refresh from LegiScan, status updates).

APPLICATIONS
- Native application form on the site (anonymous submit). Required fields include age.
- Referral source; if “friend/classmate,” optional structured field for the friend’s name
  (stored on the application row).
- Pipeline statuses: pending, invited, met_with, onboard, accepted, rejected; internal
  numeric review score optional.
- Interview invitation: moving to Invited uses send-invitation-email (Resend), with an in-app
  preview (dry_run) before send; from/cc configurable via Supabase secrets.
- Onboarding scheduling: moving to Onboard uses send-onboarding-schedule-email — congrats
  message and request for ~two weeks of availability to schedule the onboarding call
  (detailed welcome is intended for the live call).
- Rejection flow can send email via send-rejection-email; met_with date captured in UI.
- Import from application into Add Member prefills member fields.
- AI screening: DivEye / ScreenComply checks on application “additional info” and proposals
  to help flag low-quality or AI-generated text before human review.

VOLUNTEER HOURS
- Members submit hours; volunteer-permission users can approve/deny and comment.
- Database stores reviewed_by and reviewed_at; UI shows “Reviewed by” + date (and view-as
  exec dashboard enriches reviewer names via view-member-dashboard function).

MEMBERS & AUTH
- Member create/update via dashboard; members-provision Edge Function ties Auth user,
  email, welcome messaging (Resend in current setup — see function and docs/SETUP.md).
- Registration form on first login; start_date can be set when registration completes.
- Login identity is members.email (@spanationwide.org). original_email is personal/contact
  only (welcome + password-reset delivery).
- Forgot Password: LoginPage POSTs to /functions/v1/hyper-endpoint (source folder
  password-reset/). Resolves members by SPAN or personal email; prefers Auth user for
  SPAN email; may create/link Auth if missing; sets alphanumeric temp password; emails
  via Resend with explicit SPAN login address in the body. Details:
  docs/FIRST_LOGIN_AND_REGISTRATION.md §1b and docs/DEPLOYMENT.md.
- Exec membership lifecycle: honorable-exit / firing letter flows, directory deactivation
  (active = false) after confirmed exit, HR report review notes, policy notice emails.

LEAVE, CALENDAR & DASHBOARD UX
- Leave/extension requests (member_requests) with exec approve/decline.
- Unified leave calendar: birthdays, SPAN events, team-lead deadlines
  (dashboard_calendar_events + related UI).
- Dashboard dark mode, section jump nav, self-serve school/grade/location edits where enabled.

CLASSROOM (SPAN Classroom)
- Phase 1–2: schools, teachers, classes, join flow; assignments with materials/file uploads,
  grading, editing; classroom LegiScan search and student policy toolkit.
- Extends the platform beyond internal member ops into education workflows.

SECURITY / PERF (RECENT)
- Public site reads increasingly routed through safe RPCs; hardened public RLS.
- Bundle/perf work: dashboard JS cuts, WebP, public-data caching, a11y passes;
  Our Story and related page splits to reduce bloat.

MEDIUM / BLOG
- blog permission gates a Medium OTP section on the dashboard; medium-otp-arm Edge Function
  and optional Google Apps Script for forwarding login codes to the member’s SPAN email.

EDGE FUNCTIONS (DEPLOY ALL THAT YOU USE)
- members-provision, password-reset (deploy as hyper-endpoint), dashboard-view (as
  view-member-dashboard), send-rejection-email, send-invitation-email,
  send-onboarding-schedule-email, send-volunteer-verification, medium-otp-arm,
  notify-new-application, notify-hr-report, notify-resignation-request,
  fetch-legiscan-person-contact (as deployed), plus classroom-related functions if present.

DATABASE
- All schema/RLS changes live under supabase/migrations/. Recent examples: volunteers
  reviewed_by/reviewed_at; applications referral_friend_name; bill assignment and
  outreach tables; dashboard_calendar_events; classroom tables; public-read RPC hardening —
  run migrations on Supabase before relying on new columns.

DOCUMENTATION IN REPO
- docs/README.md — index of all guides; docs/README-REACT.md, docs/README-ENV.md, docs/DEPLOYMENT.md.
- docs/SETUP.md, docs/DEVELOPMENT.md, docs/DATABASE_ARCHITECTURE.md, docs/CODEBASE_ARCHITECTURE.md,
  docs/DASHBOARD_FUNCTIONS.md, docs/APPLYING_AND_APPLICATION_REVIEW.md, docs/DOCS_CHANGELOG.md,

                6. MEMBER MANAGEMENT SYSTEM
================================================================================

OBJECTIVE: Create comprehensive member management system with automated user
provisioning and registration workflow.

COMPLETED WORK:

6.1 Member Creation System
- Create new members directly from dashboard (executive directors only)
- Form includes all member fields:
  * Basic info: name, email, original_email, role
  * Dates: start date, date of birth
  * Location: city, state, school
  * Contact: phone, LinkedIn, Instagram
  * Additional: bio, notes
  * Permissions: volunteer, applications, bills, registration (checkboxes)
  * Active status: active/inactive member toggle
- Automatically triggers member provisioning pipeline:
  * Creates auth user in Supabase
  * Generates temporary password
  * Sends email invitation via Edge Function
  * Sets up Cloudflare email routing
  * Links user_id in members table

6.2 Member Registration Form
- Shows on first login if registration_complete is false
- Pre-filled with existing member data from when they were added
- Required fields:
  * Name, email, phone
  * Date of birth
  * School, city, state
  * Profile photo upload
- Optional fields:
  * Position/role
  * LinkedIn, Instagram
  * Additional info
- Features:
  * Profile photo upload to Supabase storage with validation
  * Phone number auto-formatting as user types
  * State abbreviation auto-uppercase conversion
  * Blocks access to dashboard until registration is complete
  * Automatically refreshes member data after successful registration

6.3 Member Management Interface
- Renamed "New Member Registration" to "Member Management"
- Table view showing all members
- Split into Active/Inactive sections (2-column layout)
- Scrollable sections to prevent excessive page length
- Quick action buttons for each member:
  * Edit member info and roles
  * Email member (mailto: link)
  * Text member (sms: link)
- Edit member functionality:
  * Load existing member data into form
  * Update any field including roles
  * Change active/inactive status
  * Update profile photo

6.4 SPAN Email Auto-Generation
- Format: firstname.lastname@spanationwide.org
- Auto-generates when adding member
- Updates as name is typed (unless manually edited)
- Uses first letter of last name if last name exists

6.5 Database Functions
- create_member function: Handles member creation with auth user provisioning
- update_member function: Handles member updates including roles
- Edge Function: members-provision/index.ts
  * Creates Supabase auth user
  * Generates secure temporary password
  * Sends welcome email with credentials
  * Handles Cloudflare email routing setup

- Created hr_reports table with fields:
  * report_id (primary key)

  * additional_details (text)
  * status (enum: pending, reviewed, resolved, dismissed)

8.5 Security Policies
